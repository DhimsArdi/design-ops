# Product Changelog

This file records meaningful product requirement changes.

Do not use this file for minor visual polish, refactoring, or implementation-only changes.

## 2026-09-13 — The account menu is the only door to Settings

- **The `Settings` nav row is gone from the sidebar footer** (`docs/PRD.MD` §7). Settings and the account were two rows one centimetre apart answering the same question — "this is about me, not about the work". The footer is now a single account row, and Settings lives inside the menu it opens.
- **The account menu lists the three Settings pages directly**: `General`, `Profile`, `Security`, in the same order as the Settings page's own rail, followed by `Sign out`. They link to the pages themselves rather than to `/settings`, which only ever redirected to `/settings/general` — the removed row was a detour past the page it landed on.
- **The account row now looks like the control it is.** Avatar, name, email, and a chevron; it takes the same active treatment as a nav item while you are anywhere under `/settings`, and marks which Settings page you are on inside the menu. This replaces the earlier rule that Settings was deliberately *not* repeated in the account menu — that rule existed to avoid two routes to one page, and with the row removed there is only one.
- **Nothing else in the sidebar changed.** Planning and Administration, their counts, the collapse behaviour and the header title resolution are untouched; `/settings` remains a valid route.

## 2026-09-13 — Accounts become people: Settings, a profile, and password recovery

- **A signed-in user is now somebody** (`docs/PRD.MD` §6.1, §8.10). An account used to be an access token with an email attached — the app knew nothing else about whoever was using it. Every account now has a profile: a name, a job title, a design role, and its own preferences. One new table, `profiles`, keyed by the Supabase Auth user id.
- **The account can be linked to its designer record, and that is what makes "Me" work** (§6.1). `Designer` is the person the planning data points at — home squad, project assignments, squad leadership — and `Profile.designer_id` is the optional link between the login and that person. Both directions stay optional on purpose: not every designer has a login, and not every login is a designer. An unlinked account works completely; it just doesn't appear in the people pickers.
- **The signed-in user is selectable as Squad Lead and as a supporting designer** (§14.11), shown as `Dimas Aditya (Me)`. They are not injected into those lists — they are in them because they are a designer, like everyone else. `(Me)` is a suffix on the real name and the stored value is always the real designer id; there is no `"me"` value and no fake Me record anywhere.
- **The Squad Lead and Project Design Lead fields are now searchable people pickers** rather than plain name dropdowns — avatar, name, and job title, which is what tells two designers apart. Same control in both places.
- **New Settings section** (§14.10), in the sidebar's utility footer rather than among the six workflow destinations: `General`, `Profile`, `Security`. Settings is deliberately not repeated inside the account menu — that menu is the row directly below it.
- **Preferences that actually do something.** Timezone drives the Timeline's day boundaries and its Today marker. Week start sets the first column of every date picker. Default landing page decides where the app opens. Default timeline view decides which scale the Timeline opens on, with an explicit in-session choice still winning for the rest of that visit. All stored on the profile, so they follow the person to their next machine.
- **Dark mode is switchable** (§14.10, Appearance). Every colour in the app was already a token and `globals.css` already carried a full dark palette; what was missing was the switch and something to remember it. Light stays the default and remains what the product is designed for.
- **Language is shown honestly.** English is the only selectable option; Bahasa Indonesia is visible, disabled, and marked `Coming soon` in muted type. No partial translation, and `'id'` is not treated as a supported runtime language.
- **Password recovery exists** (§6.2). `Forgot password?` on the sign-in screen leads to `/forgot-password`, whose email lands on `/reset-password`. Expired and invalid links get an explanation and a way to request a new one, not a raw Supabase error. The confirmation screen never says whether an address has an account.
- **Changing your password from inside the app re-authenticates first** (§6.2). Supabase will change a password on the strength of a valid session alone, which makes an unlocked laptop enough; asking for the current password and actually signing in with it is what stops that.
- **Design role and system role are separate fields, and always will be** (§6.1). One is a job (`Product Designer`, `UX Researcher`) and the person owns it; the other is authorization (`Admin`, `Member`, `Viewer`) and they must not. A user cannot promote themselves — not because the screen hides the control, but because `system_role` is outside the column-level UPDATE grant, so the database refuses it.
- **Every account is still an Admin.** `system_role` exists now so that Editor and Viewer, when they arrive, are a policy change rather than a schema one.

## 2026-09-13 — The product is now called DesignOps

- **Renamed from `Design Portfolio Planner` to `DesignOps`** everywhere it is shown: the sidebar wordmark, the sign-in screen, the browser tab title, and the page header's fallback. The PRD's own title (`Design Portfolio & Manpower Planner`) goes with it.
- **Name only.** No layout, navigation, component, styling, schema, routing or behaviour change — the sidebar wordmark keeps its exact type treatment and position, it just reads differently.
- **The Overview page heading stays `Design Portfolio`.** It names what is on the page — the portfolio of design work — not the application, and the nav item for that route is still `Overview`. Turning it into the product name would have put the app's own name on one page's heading and duplicated the sidebar.

## 2026-09-13 — `Delete anyway` for Designer and Stakeholder

- **A designer or stakeholder who is still in use can now be deleted** (`docs/PRD.MD` §25). The dialog still opens by naming what references them — `2 project assignments, 1 squad lead role` — but it is no longer a dead end with an `OK` button. It now states what deleting will do and offers `Delete anyway`. This removes the busywork of opening each project to detach someone before deleting them.
- **The consequence is spelled out before the button, not after.** Deleting a designer removes them from those projects and leaves any squad they led without a lead; if they were a project's Design Lead, that project becomes unassigned. Deleting a stakeholder strips them from every project's Product Owner and Project Admin lists and leaves any department they headed without a head.
- **Squad, Department and Epic stay blocked, deliberately.** A project cannot exist without an owner squad, an epic and a department, and a designer cannot exist without a home squad — so "delete anyway" there would destroy projects rather than detach them. Retire those with Inactive. See `docs/DECISIONS.md`.
- **Inactive is still the right answer for "this person has left."** It hides them from every picker and keeps project history intact. `Delete anyway` is the only action in the product that discards data the user cannot get back.

## 2026-09-13 — Data moves to Supabase; the app now requires sign-in and is shared

- **The app has a real database** (`docs/PRD.MD` §34, §35, reversing "Do not introduce Supabase, an authentication backend, or a server database for this MVP"). Data lived in one browser's `localStorage`: tied to one laptop, lost if storage was cleared, impossible to share. It now lives in Supabase (PostgreSQL), with the schema and demo seed in `supabase/schema.sql` and `supabase/seed.sql`.
- **Several people can use it at once, and see each other's edits.** A change made by one person appears for everyone else without a reload. This replaces the MVP's explicit "single Admin, single browser/device" assumption, and takes `Concurrent multi-admin editing` off the out-of-scope list.
- **Sign-in is now required** (§6). Email and password, via Supabase Auth. Accounts are created by invitation from the Supabase dashboard — **public sign-up must be switched off there**, because Row Level Security grants full access to any authenticated user. The sidebar gained the signed-in email and a Sign out action.
- **Still exactly one role.** Every signed-in user is an Admin, as before. Editor and Viewer remain future scope, and when they arrive they become database policies rather than application code.
- **Rules that were only enforced by the UI are now enforced by the database**: one Design Lead per project, a designer assigned to a project only once, one monthly target per project per month, and a weekly focus always starting on a Monday. The UI still checks first, so the error messages stay readable.
- **No screen changed.** The repository layer that `docs/PRD.MD` §34 required for exactly this purpose absorbed the move — see `docs/DECISIONS.md` for how, and for what that cost.

## 2026-09-12 — Every successful write now confirms itself with a toast

- **Writes are no longer silent** (`docs/PRD.MD` §29.2). Creating, updating, deleting or toggling any record used to close its dialog and leave the user to spot the change in the table behind it. Each successful write now raises one toast in the bottom-right corner, worded `<the thing> <what happened>` — `Sarah Chen updated`, `Trade Finance archived`, `Merchant Revamp rescheduled`. Naming the record is the point: the user knows they pressed Delete, but not always which row was focused when they did.
- **One toast per user action, not per row written.** Saving the project wizard writes assignments, monthly targets and weekly focus rows and confirms once; moving several designers into a squad confirms once, with the count.
- **Timeline's drag interactions gain the feedback they most lacked** — dragging a bar or a Weekly Focus band wrote straight to storage with no acknowledgement at all, which is the easiest place in the app to move something by accident.
- **Toasts confirm, they never ask.** Decisions stay in confirmation dialogs (§25, §33), and failed or refused writes stay reported inline where the user is working. There is no undo: destructive actions are already gated by a dialog, so the toast is a receipt, not a second chance.

## 2026-09-12 — Timeline's canvas utilities move off the toolbar into a floating dock

- **The Timeline toolbar now carries only the four controls planning needs constantly** (`docs/PRD.MD` §14.2): Search, Filter, navigate time, switch scale. A toolbar of a dozen equal-weight controls had no primary action.
- **Fit, zoom out / in and Legend move into a floating utility dock in the bottom corner of the chart** — the surface they actually act on. They stay one reach away as quiet ghost controls on a small card, and no longer compete with the primary controls above. The dock is absent while the empty state is showing, since there is nothing to fit, zoom or read a legend for. This supersedes the previous entry's "Zoom moves off the chart into the toolbar".
- **Time navigation reads as one cluster instead of three spread controls**: `Today` sits with the stepper it acts on, and the period readout is sized to the selected scale rather than to the widest label any scale can produce — so `‹ 2026 ›` no longer leaves a gap the width of `29 Sep 2026 – 5 Oct 2026` between its arrows.
- **The period readout is never truncated** (§14.2). It reserves a minimum width and grows past it instead of clamping to a fixed box, so no scale can produce a `September 20…`. The Month readout is also shortened deliberately to `Sep 2026`, matching the short month the Week readout already uses.

## 2026-09-12 — Timeline reworked around the chart: one Filter popover, a scale segmented control, and health off the bars

- **Timeline's filter toolbar collapses to Search + one `Filter` button** (`docs/PRD.MD` §14.2, §29.1). Squad, Priority, Status, Department, Epic, Health, Designer and archived visibility all move into a popover that applies immediately; the button carries the active count (`Filter · 2`) and each active dimension also shows as a removable chip under the toolbar. The permanent `Show archived` switch is gone — it is now `Include archived projects` inside the popover, which is where an edge-case visibility preference belongs.
- **Timeline gains Search**, reversing §29.1's "Timeline has no Search". It matches project name, Owner Squad, Department, Epic, and any assigned designer — a quick lookup on a chart you are already looking at, not a second filter surface.
- **Scale is a segmented control, not a dropdown** (§14.2): `Week | Month | Quarter | Year`, always showing which one you are in. **The `Day` scale is withdrawn** — see `docs/DECISIONS.md`.
- **Navigation reads as one cluster** (`Today ‹ 7 – 13 Sep 2026 ›`), the readout names the period in the selected scale's own terms, and Previous/Next step by that scale.
- **Zoom moves off the chart into the toolbar**, next to the scale control, and a new **Fit** action frames the projects currently on screen (coarsest scale their span needs, natural zoom, centred).
- **Health no longer colours the bars** (§14.2, §31). A bar now carries duration and commitment only — solid fill + solid border for Committed, light fill + dashed border for Tentative — while At Risk and Blocked show a small dot at the start of their bar and On Track shows nothing. Full health, dates, duration and commitment are in the bar's hover tooltip.
- **Weekly Focus is a quiet band, not a third bar style**: same row, same behaviour (drag to another week, click for the week dialog), but a neutral wash instead of a dotted-border bar competing with Committed/Tentative.
- **The legend is one click away** behind a `Legend` button instead of a permanent strip above the chart.
- **The chart is the page**: the timeline card owns its own toolbar and claims the height the page can give it, the project column is 320px with two-line project names, and rows are ~56px with ~28px bars. The now-line is labelled `Today` and uses the brand accent — red on this screen means Blocked.

## 2026-09-12 — Timeline becomes a real Gantt; Project gains day-level dates

- **Project's timeline is now day-level** (`docs/PRD.MD` §8.2, breaking): `start_month` / `end_month` (`"YYYY-MM"`) are replaced by `start_date` / `end_date` (`"YYYY-MM-DD"`, both ends inclusive). The month span everything else still works in — Monthly Target rows, Person Timeline, the Projects list column, Overview — is **derived** from those dates, never stored beside them, so a reschedule can't leave a month field disagreeing with the dates. Existing `localStorage` rows are migrated in place on first read (expanded to the full span of the months they already named), not discarded: unlike earlier data-shape changes in this app, nothing else in the schema moved, so wiping every entity's storage to change one would have cost more than it saved.
- **Timeline is one Gantt across five scales** (§14.2, §30) — Day / Week / Month / Quarter / Year — replacing the `[Month] [Week]` segmented control. The old Month View is the **Year** scale (month columns); the old Week View is the **Quarter** scale (week columns grouped by month). Also new: zoom within a scale (buttons, Ctrl/Cmd + wheel, trackpad pinch), a now-line at every scale, muted weekends, a timeline that extends itself as you scroll toward either edge, and a Project column you can drag wider or narrower.
- **Projects can be rescheduled by dragging or resizing their bar** (§30, reversing "drag project / resize project bar / zoom by day — not required"). Both snap to whole days and write straight back to `start_date` / `end_date`. Rescheduling never cascades — there are no dependencies between projects — and Monthly Target rows that fall outside the new range are kept rather than silently deleted; the Edit wizard, with its existing confirmation, stays the only place that drops them. **Completed and Cancelled projects are read-only on the Timeline**, because their `end_date` is a historical record written by Mark as complete.
- **Weekly Focus items are now bars**, one per week, stacked under their project's bar on the same row, at every scale below Year (at Year a week is too narrow to read, and the portfolio should stay one bar per project). A focus bar can be dragged to another week — always snapping to that week's Monday — but not resized, since a focus is one week by definition. Clicking one still opens the same week-detail dialog. `WeekGridTrack` is deleted; `MonthRangeTrack` stays, because Person Timeline (§14.6) is still month-only.
- **`dependencies` and `critical path` remain out of scope**, and `% complete` and `baselines` are now listed alongside them (§38) — the Gantt component supports all four; this product deliberately uses none. Conversely, "Drag-and-drop timeline" and "Day-level timeline view" leave the out-of-scope list.
- **Mark as complete now compares days, not months** (§17, §25): a project ending Dec 18 that completes on Dec 3 now offers to shorten its end date, where the old month comparison saw both as "2026-12" and stayed silent. Choosing "End allocations on completion date" sets `end_date` to exactly that date — the button has always said "date" while truncating to the month.
- **Projects' Timeline filter is day-accurate**: a project that ended on the 3rd now reads `Past` on the 12th, instead of staying `Active now` until the month turned over.
- **Add/Edit Project Step 2 collects dates, not months** (§22). Without this, opening Edit after a drag would silently round the bar back to month boundaries.
- Fixed a pre-existing bug in `currentWeekStart()`: it read a local instant with `getUTCDay()`, so anywhere east of Greenwich, Monday before 07:00 (WIB) resolved to the *previous* week's Monday.

## 2026-09-12 — Teams' "No designers · Add" opens an inline multi-select dialog instead of linking to Master Data

- Teams (`docs/PRD.MD` §14.7): a squad row with zero designers now opens an **Add designers** dialog in place — search Active designers and select several at once, then confirm to assign them all to that squad without leaving the page. This replaces the previous behavior of linking out to `/master-data/designers`.
- This reverses part of the earlier "People and Teams are read-only directories; all entity CRUD lives in Master Data" decision (`docs/DECISIONS.md`), specifically for squad membership only — Squad Lead assignment is unchanged and still links out to Master Data.
- Because a Designer's Home Squad is a single required field (no "unassigned" pool exists in this product), selecting a designer already in another squad moves them into the new one; the dialog shows each candidate's current squad so this is explicit, not a silent side effect.
- `MultiSelectChecklist` moved from `src/app/projects/_components/` to `src/components/shared/` since it's now shared by both the Project wizard and this new dialog.

## 2026-09-12 — Guarded Delete added to Master Data and Projects

- Designers, Squads, Departments, Epics, and Stakeholders each gain a "Delete" row action (below the existing Edit/Deactivate items, its own separator, destructive styling), and Projects gains "Delete" in both the Projects list row menu and Project Detail's overflow menu. This reverses the previous "no hard delete anywhere" rule (`docs/DECISIONS.md`), but only conditionally: **Delete is blocked whenever the record is still referenced by anything else** (a Designer's assignments or squad-lead role, a Squad's designers/owned projects, a Department's epics/projects, an Epic's projects, a Stakeholder's department-head/product-owner/project-admin references), with a dialog naming what's still using it. This preserves the original rule's goal — historical Project context never breaks — while adding the capability that was asked for.
- Deleting a Project also cascade-deletes its own Project Assignment, Monthly Target, and Weekly Focus rows (nothing else references a Project, so no usage guard applies to it). Master data referenced by the project — its Owner Squad, Epic, Department, stakeholders, designers — is untouched.
- New shared components: `ConfirmDialog` (generic yes/no) and `DeleteEntityDialog` (the blocked/confirm branching above), both built on the existing `Dialog` primitives — this app had no confirmation-before-destructive-action pattern anywhere until now (Archive/Deactivate previously fired on a single click).

## 2026-09-12 — Project lifecycle: Completed/Cancelled replace Proposed/Done, with Mark as Complete/Hold/Cancel/Reopen; Project Detail redesigned

- **Status set changed** (`docs/PRD.MD` §10, breaking): `Proposed, Planning, In Progress, On Hold, Done` → `Planning, In Progress, On Hold, Completed, Cancelled`. Proposed is retired (every new project now starts in Planning); Done is renamed Completed; Cancelled is new. Existing `localStorage` data predating this change will not match the new enum, the same caveat already accepted for earlier data-shape changes in this app.
- Project gains a `completed_at` field ("YYYY-MM-DD" or null), set by the new **Mark as complete** action and cleared by **Reopen**.
- New lifecycle actions, all on Project Detail's header overflow menu, contextual on current status: **Mark as complete** (a dialog collecting a completion date, defaulted to today; if the project's own `end_month` falls after it, offers "keep as historical" vs "end on completion date", which only ever adjusts `end_month` — there is no per-`ProjectAssignment` date field to write to instead, see `docs/DECISIONS.md`), **Put on hold** (immediate, no confirm), **Cancel project** (confirm required), **Resume project** / **Reopen project** (immediate, no confirm, non-destructive). **Archive** now requires confirmation too (previously a bare click); Unarchive stays immediate.
- **Overview**: the "Upcoming / Proposed" stat and "Upcoming Projects" list are removed (their data source, Proposed, no longer exists). "Project Health" is now a full-width section in its place. Health/Cross-squad scope changed from "not Done" to "not Completed and not Cancelled" (`isTerminalStatus`, new shared selector replacing scattered `status !== "Done"` checks in Overview/Timeline/Projects).
- **Projects list** gains an Active / Completed / All lifecycle tab (default Active = Planning + In Progress + On Hold — deliberately broader than Overview's Active Projects KPI, which stays Planning + In Progress only). The Status filter is only shown inside the All tab; switching tabs clears it. This replaces the previous implicit "Done hidden unless explicitly picked" default filter.
- **Project Detail redesigned** (`docs/PRD.MD` §14.4) into a single primary content surface (Overview / Design Team / Timeline & Monthly Targets / Weekly Plan, divided by subtle `Separator`s and section headings) plus a lightweight "Project Details" footer for Created/Updated metadata — replacing five separate bordered `ContentSection` cards. Empty-value wording standardized to `Not set` (missing configuration) / `Not assigned` (missing people) everywhere on the page, including `AssignLeadControl`'s shared "Unassigned" label (also seen on Overview and the Projects list). The Department Head snapshot caveat moved from permanent body text to an info-icon tooltip. Squad Lead now shows an avatar, matching Design Lead. Monthly Targets render as a compact scrollable row of month cards instead of a plain table, with an actionable empty state ("+ Add monthly target" linking to Edit).

## 2026-09-12 — Filter behaviour unified across all nine list screens

- Projects, Timeline, People, Teams, and the five Master Data screens now share one filter toolbar (§29.1, new) instead of the three separate patterns they had grown: `FilterSelect`/`FilterMultiSelect` (Projects/People/Teams), raw fixed-width `<Select>`s (Timeline, Stakeholders), and a bare search box (four Master Data screens). Search width, control spacing, and the reset action are identical everywhere.
- **Result counts removed.** People and all five Master Data screens no longer show an `"X of Y <entity>"` header; no screen shows a result count now. Projects, Timeline, and Teams never had one.
- **One reset action, one wording.** The former "Clear all" (Projects), "Clear filters" (Timeline/People/Teams/Stakeholders), and "Clear search" (four Master Data screens) are now a single **"Clear filters"** button in the same position on every screen. It appears whenever anything is active, including a Search query alone. Projects' Advanced Filters panel keeps its separate staged Reset/Apply footer.
- **Empty-state copy unified.** Every screen now reads `No <entities> yet` before any data exists and `No <entities> match these filters` when filtering returns nothing (previously five variants, one of them with a trailing period, plus `"No projects found"` on Projects for a state Timeline and Overview already called `"No projects yet"`). The Master Data no-match states no longer echo the query back in a description.
- **"All" dropdown wording is now rule-based** (§29.1): `All <entities>` / `All <values>` / `Any <dimension>`. Fixes `All squads` being reused for Teams' Staffing and Lead filters, `All designers` for People's Assignment filter, and Timeline's `All health` vs Projects' `All health statuses`.
- **Search is debounced everywhere** (250 ms). The five Master Data screens previously re-filtered on every keystroke. `Cmd/Ctrl+K` now focuses the search box on every screen that has one, not just Projects.
- Timeline's seven filters moved from fixed-width raw `<Select>`s to the shared dropdowns, so they read `Squad: Payments` rather than a truncated `Squad: All`, and Squad/Department/Epic/Designer became searchable. Timeline still has **no** Search box by design.
- Projects' active-filter chip row no longer appears when only a Search query is set — it previously rendered as an empty strip containing just the reset button.

## 2026-09-11 — MVP modeling decisions confirmed after pre-development audit

- Project Design Lead is optional at every Status; it is derived from Project Assignment (`project_role = "Lead"`), not a separate field on Project. Empty state is "Unassigned," never a validation error blocking save.
- Department Head moved from an independent per-project selection to Department Master Data. Projects now auto-fill Department Head from the selected Department and store it as a snapshot (does not retroactively change if the Department's head changes later).
- Defined "Active Projects" for Overview metrics as Status ∈ {Planning, In Progress}. Proposed is reported separately as "Upcoming / Proposed"; On Hold and Done are excluded.
- Done projects are now explicitly hidden by default from Overview and Timeline (filterable back in on the Projects page). They are never deleted.
- Confirmed MVP persistence: `localStorage` behind the service/repository layer, single-admin/single-browser assumption, no backend/Supabase/auth for MVP.
- Introduced Project Archive as a concept separate from Status — archiving hides a project from operational views without deleting it or changing its lifecycle Status.
- Confirmed all Master Data entities (Designers, Squads, Departments, Epics, Stakeholders) use Active/Inactive with no hard delete, even when unreferenced; Projects use Archive instead of deactivation, with no hard delete either.
